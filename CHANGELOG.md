# Changelog

What each release changed, newest first, for one question: should I update, and what will I be getting. The pull requests carry the detail.

Each release ships with a dejima release, and names it: the one it was tested with. It's N/A until the release is prepared, and a release can't be published while it is. See [docs/release.md](docs/release.md).

## 0.1.19

Released against dejima: 2026.11.06

- **Stop reaches only its own session:** the launcher finds a task's session in dejima's registry by its tmux pane and its dejima's pid together, not the pane alone. After a tmux server restart, a new task's pane could take the id of a dead pane whose session was still running, and the task's Stop, Allow and remote-access link would have acted on that session instead. ([#83](https://gitbox.branderson.io/dejima/darner/pulls/83))
- **The plugin is now `page.dejima.darner`** (was `io.branderson.dejima.darner`), after dejima's domain, dejima.page. maubot sees a new plugin, so create an instance of it, enter its config again and remove the old one. Replies to the old plugin's messages no longer work, so migrate with no sessions open, or name the session for anything still running, as in `@darner stop dn-7f3k2`. The docs call the bot darner's Matrix bot throughout. ([#84](https://gitbox.branderson.io/dejima/darner/pulls/84))
- **Config sets' descriptions in darner-web:** its Config sets page and the new-task form show each config set's description, the comment lines it starts with, beside its name. ([#89](https://gitbox.branderson.io/dejima/darner/pulls/89))
- **Writing a frontend:** [docs/frontends.md](docs/frontends.md) is what a frontend for another platform, such as Slack, must do, and what to check before running one someone else wrote: every frontend holds a key to the dejima host. Report a vulnerability to report@dejima.page. The README links a [demo of darner-web](https://darner-demo.dejima.page) that runs in the browser. ([#87](https://gitbox.branderson.io/dejima/darner/pulls/87), [#90](https://gitbox.branderson.io/dejima/darner/pulls/90), [#91](https://gitbox.branderson.io/dejima/darner/pulls/91))

## 0.1.18

Released against dejima: 2026.11.04

- **darner-web says where an ended session's files are:** its page says whether the session's `~/shared` was removed from the dejima host, because the zip holds all of it, or kept there until it's cleared. The zip's Download button and the Clear button have even padding around them. ([#80](https://gitbox.branderson.io/dejima/darner/pulls/80))
- **Clearing a session removes its `~/shared`:** a share the launcher keeps, because a session was stopped before it delivered or changed after, now waits for the session to be cleared, or for `output_retention`, and is then pruned whatever it holds. darner-web's Clear does it, and the Matrix bot has a `clear` command, which its ended notice points to when a share was kept. `POST /v1/tasks/<id>/clear` does it for any frontend, and the launcher takes `discard <id>`. If you recover files from kept shares, you now have until `output_retention` (7 days by default) to do it, rather than until you remove them. Shares of sessions started on the dejima host outside darner are never touched. The launcher's `catalog`, which the API now fetches at startup, warns when `dejima-share`, `dejima-allow` or `docker` can't be found, so a launcher missing `--dejima-share` shows in the API's log rather than only as shares left behind. ([#79](https://gitbox.branderson.io/dejima/darner/pulls/79))
- **Docs reorganised:** the README says what darner is and how its parts fit, and links out. Setup, the Matrix bot, darner-web, tasks, sessions and the reference each have a page under `docs/`, and setup no longer assumes the Matrix bot: the API's first token is named for whichever frontend you start with. ([#77](https://gitbox.branderson.io/dejima/darner/pulls/77))
- **Messages aren't kept, and darner-web says so:** what you send a session is typed into it and never stored, so it doesn't appear on the session's page. darner-web now says that beside the message box, and says Sent rather than reloading as if the message would show. ([#75](https://gitbox.branderson.io/dejima/darner/pulls/75))
- **Stopping shows it's stopping:** darner-web's Stop says it's stopping the session, and for how long, and the page shows the session ended as soon as it has, rather than up to a poll later. `POST /v1/tasks/<id>/stop` now polls before it answers, so its end is recorded by then, from any frontend. darner-web's new-task form drops Extra context, which in chat is the reply to a note and on the web only duplicated Task. ([#74](https://gitbox.branderson.io/dejima/darner/pulls/74))
- **Keywords spelled out:** `ctx:` is now `blurb:` and `deps:` is `dependency:`, in chat and in config sets. The old spellings still work, so existing config sets needn't change. `GET /v1/configs/{name}` describes a config set with the new keywords. ([#73](https://gitbox.branderson.io/dejima/darner/pulls/73))
- **Named sessions:** `name: <name>` in chat, or Name in darner-web, names a session, and `dn-<name>` then works anywhere its id does. A session holds its name until it's cleared, even once it has ended, so a command repeated later can't reach a new session that took it. ([#72](https://gitbox.branderson.io/dejima/darner/pulls/72))
- **Check now:** a session's page in darner-web can have the API look for output and requests now, rather than at the next poll, at most once every 15 seconds for each frontend. `POST /v1/tasks/<id>/check` does it for any frontend. ([#72](https://gitbox.branderson.io/dejima/darner/pulls/72))
- **Config sets that disagree are refused:** two config sets giving a single value differently, such as `harness:`, are refused, naming each set and its value, unless the request gives that value itself. A later set used to win, and darner-web sent them in alphabetical order, so which won there was an accident. ([#71](https://gitbox.branderson.io/dejima/darner/pulls/71))
- **darner-web, easier to read and on a phone:** Start says it's starting the session, and for how long, until the session's page opens. Sessions are cards, and the header stays one line. A session's page leads with what it's waiting on you for, or its newest event, then the answer box and what it was started with, and its history follows, newest first and folded, with Expand all. The API's sessions gain `started_with`, and its events `created`. ([#70](https://gitbox.branderson.io/dejima/darner/pulls/70))
- **Output a file tool can't misplace:** the agent's instructions say that `~/shared` is in its home directory, to give file-editing tools its full path, and to make the signal files in a shell and check they're there. Cline's file tools took `~/shared/.done` as a directory named `~` under the working directory, so the requester never heard the session had finished. ([#69](https://gitbox.branderson.io/dejima/darner/pulls/69))
- **Config set descriptions:** comment lines at the top of a config set are its description, shown by `describe` in chat and on darner-web's config set page. ([#68](https://gitbox.branderson.io/dejima/darner/pulls/68))
- **Harness settings that fit:** a task asking for a backend, effort level or context window its harness can't take is refused, on every frontend, rather than failing inside dejima, from what dejima's own manifests say each harness takes. darner-web lists every harness dejima has, which it didn't, and offers only what fits the harness and backend above each field, and the models `[catalog]` in `api.toml` lists for them, with a self-hosted model's context window filled in. ([#65](https://gitbox.branderson.io/dejima/darner/pulls/65))
- **Defaults are your dejima host's:** the catalog reports dejima's own default harness and each harness's settings, with the launcher's options in their place, a task naming no harness is held to dejima's default, and the launcher setup no longer pins `--harness claude-code`. If yours has it and you want dejima's default, redo step 4 without it. ([#67](https://gitbox.branderson.io/dejima/darner/pulls/67))
- **darner-web shows what Start launches:** the agent fields are changes to what config sets and defaults give, each saying what No change means, and above Start is what the task will launch, from the API's new `POST /v1/tasks/preview`: its settings and where each comes from, its grants and files, and each blurb, folded. ([#67](https://gitbox.branderson.io/dejima/darner/pulls/67))
- **Nearly airgapped sessions:** `network: named` drops dejima's own allowlist, so a session reaches only what its task names, and `network: sealed` also refuses to start one that could look up any name. From chat, darner-web and config sets. Needs a dejima with `--drop-domains` and `--require-sealed`. ([#66](https://gitbox.branderson.io/dejima/darner/pulls/66))
- **A delivered session's `~/shared` goes too:** when a session ends and its output has been delivered whole, the launcher has dejima prune its share from the dejima host. A share whose output wasn't delivered, or that changed afterwards, is kept for you to recover, and `--keep-shared` keeps them all. It needs a dejima release with `dejima-share prune --isolated [share]` and `--yes`, and a launcher given `--dejima-share` with its full path. ([#60](https://gitbox.branderson.io/dejima/darner/pulls/60))
- **darner-web:** a browser frontend that does everything the bot does and more: its sessions at a glance with each one's events so far, starting tasks, messages and help answers, uploads, domain decisions, stopping and clearing sessions, full blurbs and config sets, and the self-test. Its own container and token, behind a proxy that authenticates and authorizes; see `docs/web.md`. ([#59](https://gitbox.branderson.io/dejima/darner/pulls/59), [#61](https://gitbox.branderson.io/dejima/darner/pulls/61))
- **Sessions stuck starting are seen:** a session stuck at one of dejima's own prompts is reported as waiting, can be stopped, and counts toward `max_session_age`. A session whose output can never be fetched is ended at that age, with the reason posted. ([#54](https://gitbox.branderson.io/dejima/darner/pulls/54))
- **Nothing about a session outlives it:** when a session ends, the API deletes its prompt, context and every event but output its frontend hasn't collected, and the launcher deletes its task directory. The rest goes once the output is collected, or after `output_retention` (7 days by default). ([#51](https://gitbox.branderson.io/dejima/darner/pulls/51))
- **A note's quote isn't part of the task:** a note that replies to someone carried their quoted message into the task, even if they weren't allowlisted. ([#53](https://gitbox.branderson.io/dejima/darner/pulls/53))
- **Audit log:** the API logs who started, typed into, uploaded to, stopped or decided domains for each session, without what was typed or uploaded. ([#55](https://gitbox.branderson.io/dejima/darner/pulls/55))
- **Policy covers internal grants and dependencies:** `[policy]` gains `allow_internal`, `max_internal_domains`, `allow_domains` and `allow_dependency_kinds`, and refuses a misspelled key. `tarball:` dependencies are now refused unless `allow_dependency_kinds` lists them. ([#56](https://gitbox.branderson.io/dejima/darner/pulls/56))
- **Pinned dependencies and a tighter systemd unit:** the API image, the systemd install and CI install dependencies pinned with hashes, and `examples/darner-api.service` is as confined as the container. Under systemd, update with the README's new install commands. ([#57](https://gitbox.branderson.io/dejima/darner/pulls/57))
- **Fixes from the release review:** a domain request naming one domain twice, once as internal, can no longer have it granted as internal when policy refuses that, and `max_internal_domains` now also holds for grants after launch, including two approved at once. An output too large for the API no longer stops the API polling every session, and a session whose output can't be collected is still stopped at `max_session_age`. `stop` refuses a running session whose container it can't find, rather than leaving that container running. A new launcher option, `--done-interval` (60 seconds by default), limits how often a running session's `.done` is collected, and the API keeps a session's latest five output zips, deleting each once its frontend collects it. An older output keeps its summary but no longer offers its zip. The API's errors are JSON, so `tell`, `stop` and `upload` on a session that's gone say so rather than failing to parse. Help and darner-web list each harness's effort levels from its manifest. ([#76](https://gitbox.branderson.io/dejima/darner/pulls/76))
- **Releases only from `main` and `development`,** never from a pushed tag. ([#52](https://gitbox.branderson.io/dejima/darner/pulls/52))
- **Renamed to darner,** with the bot as dragonlet: the plugin id is `io.branderson.dejima.darner` (was `io.example.meeseeks`), with `darner-api`, `darner-launch` and `dn-` task ids. maubot sees a new plugin, so create an instance of it, enter its config again and remove the old one. Tasks in an old database aren't carried over. ([#48](https://gitbox.branderson.io/dejima/darner/pulls/48))
- **Sessions stop after a day:** a session that's still running after `max_session_age` (a day by default) is stopped, and the bot says so, so none is left running forgotten. A task id that isn't one, such as `stop ab-12345`, gets a reply instead of starting a new session. ([#50](https://gitbox.branderson.io/dejima/darner/pulls/50))
- **Weak API tokens refused:** the API won't start if a token in `[tokens]` is shorter than 32 characters, is `examples/api.toml`'s placeholder, or is shared by two frontends. If yours is refused, generate a new one with `openssl rand -hex 32` and set it in both `api.toml` and the bot's config. ([#46](https://gitbox.branderson.io/dejima/darner/pulls/46))
- **Frontend self-test:** `@bot selftest`, or `POST /v1/selftest`, sends text written like a hostile agent's through the paths an agent's text takes, with each line saying what a safe frontend shows. ([#47](https://gitbox.branderson.io/dejima/darner/pulls/47))
- **Looking things up from chat:** `list configs` and `list blurbs` name the config sets and context blurbs, and `describe <names>` shows what each config set applies and what each blurb says. ([#43](https://gitbox.branderson.io/dejima/darner/pulls/43))
- **Waiting notices:** the bot says when a session's screen has stopped changing, with the end of its screen, so a question asked at the agent's own prompt isn't missed. ([#36](https://gitbox.branderson.io/dejima/darner/pulls/36))
- **Settings defaults:** every optional API setting has a default, and the API logs the settings it uses and warns about unknown keys. `configs_dir` defaults to `configs` beside `blurbs_dir`. ([#36](https://gitbox.branderson.io/dejima/darner/pulls/36))
- **Config sets:** `config: <name>` applies a named set of keyword lines, which can also give each session files such as an API token. ([#34](https://gitbox.branderson.io/dejima/darner/pulls/34), [#35](https://gitbox.branderson.io/dejima/darner/pulls/35))
- **Internal domains at launch and ports:** `internal:` grants internal domains, domains can carry a port, and help lists the harnesses and backends. ([#33](https://gitbox.branderson.io/dejima/darner/pulls/33))
- **Pre-releases:** every merge to `development` publishes a pre-release of the plugin. ([#32](https://gitbox.branderson.io/dejima/darner/pulls/32))
- **Only a direct mention acts:** the bot acts on a message that mentions it with a pill or its full user ID, not on its display name or a bare reply. ([#42](https://gitbox.branderson.io/dejima/darner/pulls/42))
- **Cline's questions answered from chat, and its settings:** a reply to cline's question is typed into it, text is typed as written, and tasks and config sets can set cline's context window and its effort levels. ([#38](https://gitbox.branderson.io/dejima/darner/pulls/38), [#40](https://gitbox.branderson.io/dejima/darner/pulls/40), [#41](https://gitbox.branderson.io/dejima/darner/pulls/41))
