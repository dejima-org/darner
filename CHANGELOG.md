# Changelog

What each release changed, newest first, for one question: should I update, and what will I be getting. The pull requests carry the detail.

Each release names the dejima release it was released against: the one it was tested with, which has everything it needs from dejima. It's N/A until that dejima release exists, and a release can't be published while it is. See [docs/release.md](docs/release.md).

## 0.1.18

Released against dejima: N/A

- **Named sessions:** `name: <name>` in chat, or Name in darner-web, names a session, and `dn-<name>` then works anywhere its id does. No two of a frontend's open sessions share a name.
- **Check now:** a session's page in darner-web can have the API look for output and requests now, rather than at the next poll, at most once every 15 seconds for each frontend. `POST /v1/tasks/<id>/check` does it for any frontend.
- **Config sets that disagree are refused:** two config sets giving a single value differently, such as `harness:`, are refused, naming each set and its value, unless the request gives that value itself. A later set used to win, and darner-web sent them in alphabetical order, so which won there was an accident.
- **darner-web, easier to read and on a phone:** Start says it's starting the session, and for how long, until the session's page opens. Sessions are cards, and the header stays one line. A session's page leads with what it's waiting on you for, or its newest event, then the answer box and what it was started with, and its history follows, newest first and folded, with Expand all. The API's sessions gain `started_with`, and its events `created`.
- **Output a file tool can't misplace:** the agent's instructions say that `~/shared` is in its home directory, to give file-editing tools its full path, and to make the signal files in a shell and check they're there. Cline's file tools took `~/shared/.done` as a directory named `~` under the working directory, so the requester never heard the session had finished.
- **Config set descriptions:** comment lines at the top of a config set are its description, shown by `describe` in chat and on darner-web's config set page.
- **Harness settings that fit:** a task asking for a backend, effort level or context window its harness can't take is refused, on every frontend, rather than failing inside dejima, from what dejima's own manifests say each harness takes. darner-web lists every harness dejima has, which it didn't, and offers only what fits the harness and backend above each field, and the models `[catalog]` in `api.toml` lists for them, with a self-hosted model's context window filled in.
- **Defaults are your dejima host's:** the catalog reports dejima's own default harness and each harness's settings, with the launcher's options in their place, a task naming no harness is held to dejima's default, and the README's launcher setup no longer pins `--harness claude-code`. If yours has it and you want dejima's default, redo step 4 without it.
- **darner-web shows what Start launches:** the agent fields are changes to what config sets and defaults give, each saying what No change means, and above Start is what the task will launch, from the API's new `POST /v1/tasks/preview`: its settings and where each comes from, its grants and files, and each blurb, folded.
- **Nearly airgapped sessions:** `network: named` drops dejima's own allowlist, so a session reaches only what its task names, and `network: sealed` also refuses to start one that could look up any name. From chat, darner-web and config sets. Needs a dejima with `--drop-domains` and `--require-sealed`.
- **A delivered session's `~/shared` goes too:** when a session ends and its output has been delivered whole, the launcher has dejima prune its share from the dejima host. A share whose output wasn't delivered, or that changed afterwards, is kept for you to recover, and `--keep-shared` keeps them all. It needs a dejima release with `dejima-share prune --isolated [share]` and `--yes`, and a launcher given `--dejima-share` with its full path. ([#60](https://gitbox.branderson.io/dejima/darner/pulls/60))
- **darner-web:** a browser frontend that does everything the bot does and more: its sessions at a glance with each one's events so far, starting tasks, messages and help answers, uploads, domain decisions, stopping and clearing sessions, full blurbs and config sets, and the self-test. Its own container and token, behind a proxy that authenticates and authorizes; see `docs/web.md`. ([#59](https://gitbox.branderson.io/dejima/darner/pulls/59), [#61](https://gitbox.branderson.io/dejima/darner/pulls/61))
- **Sessions stuck starting are seen:** a session stuck at one of dejima's own prompts is reported as waiting, can be stopped, and counts toward `max_session_age`. A session whose output can never be fetched is ended at that age, with the reason posted. ([#54](https://gitbox.branderson.io/dejima/darner/pulls/54))
- **Nothing about a session outlives it:** when a session ends, the API deletes its prompt, context and every event but output its frontend hasn't collected, and the launcher deletes its task directory. The rest goes once the output is collected, or after `output_retention` (7 days by default). ([#51](https://gitbox.branderson.io/dejima/darner/pulls/51))
- **A note's quote isn't part of the task:** a note that replies to someone carried their quoted message into the task, even if they weren't allowlisted. ([#53](https://gitbox.branderson.io/dejima/darner/pulls/53))
- **Audit log:** the API logs who started, typed into, uploaded to, stopped or decided domains for each session, without what was typed or uploaded. ([#55](https://gitbox.branderson.io/dejima/darner/pulls/55))
- **Policy covers internal grants and dependencies:** `[policy]` gains `allow_internal`, `max_internal_domains`, `allow_domains` and `allow_dependency_kinds`, and refuses a misspelled key. `tarball:` dependencies are now refused unless `allow_dependency_kinds` lists them. ([#56](https://gitbox.branderson.io/dejima/darner/pulls/56))
- **Pinned dependencies and a tighter systemd unit:** the API image, the systemd install and CI install dependencies pinned with hashes, and `examples/darner-api.service` is as confined as the container. Under systemd, update with the README's new install commands. ([#57](https://gitbox.branderson.io/dejima/darner/pulls/57))
- **Sessions stop after a day:** a session that's still running after `max_session_age` (a day by default) is stopped, and the bot says so, so none is left running forgotten. A task id that isn't one, such as `stop ab-12345`, gets a reply instead of starting a new session. ([#50](https://gitbox.branderson.io/dejima/darner/pulls/50))
- **Weak API tokens refused:** the API won't start if a token in `[tokens]` is shorter than 32 characters, is `examples/api.toml`'s placeholder, or is shared by two frontends. If yours is refused, generate a new one with `openssl rand -hex 32` and set it in both `api.toml` and the bot's config. ([#46](https://gitbox.branderson.io/dejima/darner/pulls/46))
- **Frontend self-test:** `@bot selftest`, or `POST /v1/selftest`, sends text written like a hostile agent's through the paths an agent's text takes, with each line saying what a safe frontend shows. ([#47](https://gitbox.branderson.io/dejima/darner/pulls/47))
- **Looking things up from chat:** `list configs` and `list blurbs` name the config sets and context blurbs, and `describe <names>` shows what each config set applies and what each blurb says. ([#43](https://gitbox.branderson.io/dejima/darner/pulls/43))
- **Waiting notices:** the bot says when a session's screen has stopped changing, with the end of its screen, so a question asked at the agent's own prompt isn't missed. ([#36](https://gitbox.branderson.io/dejima/darner/pulls/36))
- **Settings defaults:** every optional API setting has a default, and the API logs the settings it uses and warns about unknown keys. `configs_dir` defaults to `configs` beside `blurbs_dir`. ([#36](https://gitbox.branderson.io/dejima/darner/pulls/36))
- **Config sets:** `config: <name>` applies a named set of keyword lines, which can also give each session files such as an API token. ([#34](https://gitbox.branderson.io/dejima/darner/pulls/34), [#35](https://gitbox.branderson.io/dejima/darner/pulls/35))
- **Internal domains at launch and ports:** `internal:` grants internal domains, domains can carry a port, and help lists the harnesses and backends. ([#33](https://gitbox.branderson.io/dejima/darner/pulls/33))
- **Pre-releases:** every merge to `development` publishes a pre-release of the plugin. ([#32](https://gitbox.branderson.io/dejima/darner/pulls/32))
